Which model does a worker run?

How Claude Code picks a delegated agent's model, and why the cost hid in plain sight.

If nothing on the way down names a model, a worker silently runs the same model as the conversation that called it. That is how a rule written only in prose became a usage bill.[2][4]

Where you are: a standalone explanation page in docs/. The story is in docs/LEARNING_LOG.md (2026-11-17), the decision in ADR 0006, the rules in hangar/blueprints/adapters/claudecode.md.

Two words first

Lead agent

The agent in conversation with the person: the session's main thread. In Free Wings, the-architect by default.[1]

Worker

An agent the lead agent delegates to. It works alone, in its own context, and returns one report. Claude Code calls it a subagent.[1][5]

The order Claude Code follows

When a worker starts, Claude Code looks for its model in this order and stops at the first one it finds (Claude Code docs, verified 2026-11-17):[2]

  1. The model passed on the call
    Chosen by the lead agent at the moment it delegates.
  2. The model in the agent's own file
    Frontmatter of .claude/agents/<name>.md, which construct generates.
  3. The variable CLAUDE_CODE_SUBAGENT_MODEL
    An environment setting, if someone set it.
  4. The conversation's model
    The fallback: whatever the lead agent itself is running.

With CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1, step 1 is switched off: the lead agent cannot pass a model at all.[2][3]

What happened on Chacal

  1. Passed on the callnothing
    The blueprint said "recommend, don't delegate", so nothing told the lead agent which model to pass, and it delegated anyway.[4]
  2. Agent filenothing
    No agent file had a model field yet.[4]
  3. Environment variablenothing
    Not set (inferred: the worker fell through to step 4).[7]
  4. Conversation's modelused
    So engenir and tester ran on the session's own model, the same one chosen for judgment and conversation.[4][7]

Nothing on screen said so: a worker returns a summary to the conversation that called it, not its model.[5] The cost only showed up afterward: 90% of the 5-hour limit, 65% of the weekly one, and /usage putting 66% on engenir and 24% on tester (not re-measured here).[4]

Prose versus configuration

A rule in prose

"Recommend, don't delegate" was text inside the blueprint. The model reads it, weighs it, and can still act otherwise. Nothing stops it.[4]

A rule in configuration

A model field, a deny rule such as Agent(programmer), a tools allowlist. The tool applies these whether the model agrees or not.[5][6]

What Free Wings does now

Each agent's file carries its own model and effort (step 2), and the-architect does not pass a model when it delegates (step 1), except in a deliberate escalation it tells the person about. The worker's own file decides.[4][6]

These are starting points, grounded in docs/research/2026-11-17-model-choice-per-agent.md. They change one agent at a time, by measuring.[6][7] When to go up: if the agent had all the context and still got it wrong, a larger model; if it skipped a step or a file, a higher effort (Anthropic's guidance, as recorded in the adapter).[6]

Still open

  • Whether effort in an agent file applies when that agent runs as the lead agent (--agent). Not documented, not tested.[6][4]
  • A reliable per-agent cost measure. Without one, a model change cannot really be measured: /usage attributes by agent only approximately, and per-agent figures need OpenTelemetry.[8]
